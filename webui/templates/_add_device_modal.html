{# Inline log-source discovery - a SIBLING of the form (own , POSTs to /devices/discover). Log sources are never entered manually: the device is registered from the syslog stream by hostname. #}
Log-source devices are not entered manually: they are discovered from the syslog stream by hostname. On the firewall, configure remote logging to this Gateshift host (UDP port 514), make sure the relevant rules log, let traffic flow for a few minutes, then discover.
{# Capture upload - the UI alternative to copying files into syslog-ng/logs/ by hand. Own multipart form (sibling pattern of the ASA uploader); the endpoint pre-checks the format, places the file next to the live-received logs and runs discover. #}
…or upload a syslog capture file: it is placed next to the live-received logs and scanned right away.
{# Inline OPNsense uploader - sibling form, same reason as the ASA one. For projects where the box being replaced is no longer reachable: the exported configuration goes through the same parser as the API path. #}
Export it on the firewall under System > Configuration > Backups. Secrets are stripped before anything is stored - private keys, pre-shared keys and password hashes never reach the database.
To use this firewall as a migration target as well, add an API key and secret on its device row afterwards: pushing needs the box, reading it does not.
